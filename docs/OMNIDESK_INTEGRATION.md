# Инструкция по настройке автоматического создания статей BookStack из Omnidesk

Данная инструкция описывает настройку правила в панели управления Omnidesk для автоматической генерации и публикации статей базы знаний BookStack при закрытии обращения.

---

## 1. Параметры вебхука Bridge.LM

- **URL эндпоинта:** `http://<ВАШ_СЕРВЕР_ИЛИ_ДОМЕН>:3000/api/omnidesk/webhook`
- **HTTP-метод:** `POST`
- **Формат данных:** `JSON` или URL-параметры
- **Аутентификация (опционально):** Если в файле `.env` на сервере Bridge.LM задан параметр `OMNIDESK_WEBHOOK_SECRET`, то секрет можно передать любым удобным способом:
  - В URL как query-параметр: `.../api/omnidesk/webhook?secret=ВАШ_СЕКРЕТ`
  - В HTTP-заголовке: `X-Omnidesk-Secret: ВАШ_СЕКРЕТ`
  - В теле JSON: `{"case_id": "{case_id}", "secret": "ВАШ_СЕКРЕТ"}`

---

## 2. Пошаговая настройка правила в Omnidesk

1. Откройте панель управления Omnidesk с правами администратора.
2. Перейдите в раздел: **Настройки** → **Правила** → **Правила для измененных обращений**.
3. Нажмите кнопку **«Добавить правило»**.
4. Задайте понятное название правила, например:
   `Автосоздание статьи в BookStack при закрытии`

### 2.1. Условия правила (Когда срабатывает)

Рекомендуется настроить следующие условия:
- **Статус обращения:** `изменился на` → `Закрыт` (или `Решен`)
- **Теги обращения:** `содержит` → `wiki` (или `бз`, `в базу знаний` — чтобы статьи создавались только по важным инцидентам, помеченным оператором)
- **Теги обращения:** `не содержит` → `wiki-created` (защита от повторного срабатывания, так как Bridge.LM автоматически проставляет этот тег после создания статьи)

> [!TIP]
> Если вы хотите генерировать статьи для абсолютно всех закрытых обращений определенной категории/департамента без явного тега, замените условие по тегу на выбор соответствующей **Категории** или **Группы**. Встроенный AI Triage в Bridge.LM автоматически отсеет спам и неинформативные тикеты.

### 2.2. Действие правила (Что делать)

В блоке **«Действия»** выберите:
- **Действие:** `Отправить webhook`
- **URL вебхука:** `http://<ВАШ_СЕРВЕР>:3000/api/omnidesk/webhook` (или `https://.../api/omnidesk/webhook?secret=...`)
- **Метод:** `POST`
- **Тело запроса (JSON):**
```json
{
  "case_id": "{case_id}"
}
```

> [!NOTE]
> Переменная `{case_id}` автоматически подставляется Omnidesk. Если вы используете секретный ключ в JSON, тело может выглядеть так:
> ```json
> {
>   "case_id": "{case_id}",
>   "secret": "ВАШ_СЕКРЕТ"
> }
> ```

5. Нажмите **«Сохранить правило»**.

---

## 3. Как работает сквозной цикл обработки

1. **Мгновенный ответ (202 Accepted):** При срабатывании правила Omnidesk отправляет POST-запрос. Сервер Bridge.LM подтверждает прием задачи за считанные миллисекунды, гарантируя отсутствие таймаутов в Omnidesk.
2. **Фоновая загрузка (Omnidesk API Pull):** Сервер в фоновом режиме загружает полную историю переписки, роли участников, внутренние заметки и скриншоты/вложения инцидента.
3. **AI Triage (Валидация ценности):** Модель Gemini проверяет, содержит ли тикет техническое решение. Спам, пустые тикеты и отмененные клиентом заявки отсеиваются без замусоривания BookStack.
4. **Автономное размещение (Autonomous Placement):** ИИ сопоставляет тему с существующими книгами и главами в BookStack, либо автоматически создает новый тематический раздел.
5. **Генерация и публикация статьи:** Gemini синтезирует структурированную статью по регламенту (проблема, причины, решение, рекомендации, callout-блоки) и публикует страницу в BookStack.
6. **Обратная связь в тикет Omnidesk:**
   - В тикет добавляется внутренняя заметка с прямой ссылкой на созданную статью BookStack:
     `🤖 Bridge.LM: На основе данного обращения автоматически создана статья в BookStack: [Название](URL)`
   - К тикету добавляется тег `wiki-created`.

## 4. Диагностика и проверка работы

Вы можете проверить доступность вебхука в браузере или через консоль:
```bash
curl http://<ВАШ_СЕРВЕР>:3000/api/omnidesk/webhook
```
Ответ:
```json
{
  "status": "active",
  "endpoint": "/api/omnidesk/webhook",
  "methodsSupported": ["POST", "GET"],
  "description": "Bridge.LM Webhook для автоматического создания статей BookStack по правилам Omnidesk",
  "requiredParams": "case_id (или ticket_id)",
  "auth": "secret (query, x-omnidesk-secret заголовок или body.secret)"
}
```

Логи работы фонового конвейера доступны через Docker:
```bash
docker compose logs -f app
```
В логах подробно отображаются все фазы: загрузка тикета, AI Triage, генерация статьи, выбор разделов BookStack и добавление заметки в Omnidesk.
