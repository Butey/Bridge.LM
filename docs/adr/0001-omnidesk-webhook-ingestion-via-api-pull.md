# 0001. Прием вебхука Omnidesk через ID тикета и асинхронный API Pull

## Контекст и решение
При закрытии обращения в Omnidesk правило автоматизации отправляет HTTP POST вебхук на сервер Bridge.LM. Генерация качественной статьи в Gemini занимает от 15 до 35 секунд, тогда как вебхуки Omnidesk имеют жесткий сетевой таймаут (5–10 секунд), а шаблоны тела вебхука не поддерживают передачу бинарных вложений (скриншоты, файлы логов) и могут ломаться при наличии спецсимволов в тексте переписки.

Мы решили:
1. Вебхук принимает только идентификатор обращения (`case_id` или `ticket_id`) и секретный токен авторизации.
2. Сервер немедленно возвращает ответ `202 Accepted`, предотвращая таймауты и повторные отправки (retry storms) со стороны Omnidesk.
3. Сервер асинхронно в фоновом режиме обращается к Omnidesk API (`/api/cases/{case_id}.json` и `/messages.json`), выгружая полную историю диалога с ролями участников и вложенные файлы (скриншоты, PDF) для передачи в мультимодальный контекст Gemini.

## Последствия
- Позволяет стабильно передавать изображения и вложения инцидента прямо в модель Gemini.
- Требует наличия настроенных учетных данных Omnidesk API на стороне сервера Bridge.LM (в `.env` или настройках).
