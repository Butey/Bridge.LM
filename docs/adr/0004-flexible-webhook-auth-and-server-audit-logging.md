# 0004. Гибкая авторизация вебхука Omnidesk и серверное логирование

## Контекст и решение
При настройке правил и действий "Отправить Webhook" в интерфейсе Omnidesk администраторы могут использовать разные способы передачи параметров безопасности (URL query-параметры, кастомные HTTP-заголовки или JSON-тело). Требовалось обеспечить безопасную аутентификацию входящих вызовов без излишних ограничений на стороне Omnidesk и определить формат мониторинга работы автоматизации.

Мы решили:
1. Поддерживать гибкую аутентификацию вебхука. Секрет извлекается по приоритету:
   - Заголовок `X-Omnidesk-Secret` или `Authorization: Bearer <token>`
   - Query-параметр URL: `?secret=<token>`
   - Поле в теле JSON: `req.body.secret`
2. Секрет сверяется со значением `OMNIDESK_WEBHOOK_SECRET` из окружения (`.env`) или `settings.json`. Если переменная настроена, любой запрос с неверным или отсутствующим токеном отклоняется с кодом `401 Unauthorized`.
3. Мониторинг и аудит работы фонового пайплайна ведутся исключительно через подробное серверное логирование (stdout / лог-файл) с таймингами, идентификаторами обращений и ссылками на созданные статьи в BookStack, без усложнения фронтенд-интерфейса.

## Последствия
- Максимальное удобство настройки правил в панели управления Omnidesk при сохранении защиты от несанкционированного вызова генерации Gemini.
- Отсутствие необходимости расширения React UI для просмотра очереди вебхуков.
