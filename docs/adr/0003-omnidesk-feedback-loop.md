# 0003. Обратная связь в Omnidesk через внутреннюю заметку и тег завершения

## Контекст и решение
После успешной генерации и сохранения статьи в BookStack сотрудники поддержки должны знать, что статья была успешно создана, где именно она находится и по какой ссылке доступна. Также необходимо предотвратить повторное срабатывание автоматических правил Omnidesk по тому же обращению.

Мы решили:
1. При успешном создании статьи в BookStack сервер Bridge.LM обращается к Omnidesk API (`POST /api/cases/{case_id}/notes.json`).
2. В тикет добавляется внутренняя заметка (видимая только сотрудникам) с форматированием:
   `🤖 Bridge.LM: На основе данного обращения автоматически создана статья в BookStack: [Название статьи](URL_статьи)`
3. К тикету добавляется тег `wiki-created` (через API обновления тикета).
4. Правило Omnidesk в качестве условия исключения проверяет: `Теги не содержат: wiki-created`. Это гарантирует идемпотентность и исключает повторную генерацию при случайных повторных сохранениях/закрытиях тикета.

## Последствия
- Полная прозрачность процесса для операторов службы поддержки.
- Гарантия идемпотентности: тикет никогда не генерирует статью повторно.
