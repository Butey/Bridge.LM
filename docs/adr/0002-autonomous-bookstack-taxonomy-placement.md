# 0002. Автономное размещение и автосоздание таксономии в BookStack

## Контекст и решение
При автоматическом создании статей из закрытых тикетов Omnidesk встал выбор: складировать ли все статьи в одну общую временную книгу (Inbox) для ручной сортировки оператором или доверить распределение ИИ.

Мы решили:
1. Использовать стратегию **полного автономного авто-размещения (Autonomous Taxonomy Placement)**.
2. Перед генерацией сервис запрашивает актуальное дерево существующих Книг и Глав BookStack и передает его в Gemini.
3. Модель Gemini подбирает наиболее подходящую Книгу и Главу.
4. Если подходящей категории не существует, модель предлагает создание новой Книги и/или Главы (`newBookName`, `newChapterName`). Сервер Bridge.LM создает их через BookStack API и размещает созданную статью в них.
5. Для обеспечения прозрачности и аудита каждой статье автоматически присваиваются теги происхождения (`Source: Omnidesk`, `Case: #{case_id}`).

## Последствия
- Полное устранение ручного труда по распределению статей по разделам базы знаний.
- Возможность появления новых разделов в BookStack при возникновении принципиально новых классов инцидентов.
